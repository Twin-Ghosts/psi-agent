# 草案：Cursor 风格任务进程（reasoning 压缩 + kind）

**状态**：设计已拍板并开工  
**产品一句**：用户看到的「思考」= **任务执行过程**（跳动进程行），不是长段模型独白。  
**协议一句**：**保留** thinking + tool 进度压缩进同一 `reasoning` 槽（Session 出口贴近 AI 层 OpenAI 形，便于后续层级同构 / 把全过程 reasoning 当上游输入）；用正交 **`kind`** 给 UI 白名单，不靠正文黑名单。

---

## 1. 为什么还压缩进 `reasoning`

上级对齐：不是疏忽，而是为 **Session↔AI 协议同构** 留口——过程流仍是一条 `reasoning`，以后可能整段复用为「上游 AI 输入」；若拆成独立 SSE `type=tool`，同构成本更高。

渲染与协议解耦：协议读 `reasoning`；UI 读 `kind`。

## 2. `kind` 取值（Session 打标）

| kind | 来源 | spa-v2 |
|------|------|--------|
| `thinking` | 上游 `delta.reasoning`（或上游已带 `kind`） | **尾行**「规划下一步…」（不渲染 thinking 正文；**不**封进历史行） |
| `tool_call` | Session 执行 tool 前 | **封存一行**工具短句（见 §3）；尾行仍「规划下一步…」 |
| `tool_result` | Session 执行 tool 后 | **不**封存「整理结果…」；尾行回到「规划下一步…」（刻意冷静，与实现一致） |

规则写在 **yield 点**（`agent.py` / `schedule_registry.py`），不是扫字符串分类。

> **命名注意**：SSE / `AgentChunk.kind`（上表）≠ JSONL 消息 `kind`（`chat` / `schedule.display` / …）。后者管历史白名单。

## 3. 进程行文案表（必须给定，对标 Cursor）

**原则**：上面是可封存的活动概括行；**底下尾行**才是「规划下一步…」/「撰写回复…」+ 跳动点。**永不**把 thinking 独白 / `[Tool Call:]` 原文渲成进程行；`kind` 决定切状态，短句由前端从 `tool_call` 正文解析（过渡期仍可读 marker）。

| 时机 | 触发 | 显示 |
|------|------|------|
| 回合开始 / 等首包 | `emptyProgressLog()` | 无封存行；尾行 **规划下一步…** |
| 模型 thinking | `kind=thinking` | 尾行 **规划下一步…**（不封存） |
| 调工具 | `kind=tool_call` | 封存一行（如 `读取 \`a.py\`` / `执行 \`…\``）；尾行仍 **规划下一步…** |
| 工具返回 | `kind=tool_result` | 不封存；尾行 **规划下一步…** |
| 开始吐正文 | `kind=content`（首个 content） | 尾行 **撰写回复…**；正式气泡仍可延后露出 |
| 回合结束 / 停止 | finally | 清空过程轴 |

词表与封存逻辑集中在 spa-v2 `services/turnProgress.ts`（`TURN_PROGRESS` + `summarizeToolCallText`）；改文案只改该文件。

## 4. 展示壳

流式过程轴：封存行 + 尾行跳动点。**刻意为之**：流式中 `hideAgentProse` 藏助手正文与附件 chip，回合结束后再露；`preferResultBelowRule` 仅展示层（短计划在 `---` 上 → 偏好展示下半段，不改 JSONL）。

## 5. 代码落点

| 层 | 改动 |
|----|------|
| `session/protocol.py` | `REASONING_KIND_*`；`AgentChunk.kind`；`DeltaMessage.kind`；`AiDelta.kind` |
| `session/ai_client.py` | 透传上游 `delta.kind` |
| `session/agent.py` / `schedule_registry.py` | yield 时打 kind |
| `session/channel_adapter.py` | SSE 写出 `kind` |
| `channel/_types.py` / `_core.py` | `ReasoningChunk.kind`；buffer key `reasoning:<kind>` |
| `gateway/_chat_manager.py` | SPA 事件带 `kind` |
| spa-v2 `turnProgress.ts` | **文案表** + kind→label；FocusChatThread 进程行 |

过渡期仍可保留 `[Tool Call:]` 文案（旧剥标记 / 解析工具名）；新 UI 以 `kind` + 上表为准。
